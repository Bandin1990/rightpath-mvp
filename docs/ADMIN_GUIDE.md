# ระบบหลังบ้านของสิทธิไปต่อ

ระบบหลังบ้านอยู่ที่ `/admin` และใช้สำหรับตรวจสอบ เพิ่ม แก้ไข ตรวจทาน เผยแพร่ หรือยกเลิกข้อมูลภัยเร่งด่วน หน่วยงาน ช่องทางติดต่อ และคำสำคัญที่ใช้จับคู่ข้อความของประชาชน

## ขอบเขตข้อมูล

ระบบหลังบ้านเก็บเฉพาะองค์ความรู้สาธารณะและบัญชีเจ้าหน้าที่ใน Supabase Auth ไม่เก็บเรื่องเล่า เสียง คำตอบ หนังสือร้องเรียน หลักฐาน หรือข้อมูลติดต่อของประชาชน

ข้อมูลฉุกเฉินอยู่ในตารางต่อไปนี้

- `knowledge.emergency_contacts`
- `knowledge.emergency_contact_channels`
- `knowledge.emergency_threat_groups`
- `knowledge.emergency_threats`
- `knowledge.emergency_threat_keywords`

หน้าประชาชนอ่านเฉพาะรายการที่มีสถานะ `published` ผ่าน view แบบ `security_invoker` ใน schema `api` หากฐานข้อมูลไม่พร้อม ระบบใช้ชุดข้อมูลที่ตรวจสอบแล้วซึ่งรวมมากับแอป

## เปิดใช้งาน

1. สร้างโครงการ Supabase และกำหนด `SUPABASE_URL` กับ `SUPABASE_PUBLISHABLE_KEY` ใน environment ของ Server เท่านั้น
2. ใช้ migrations ทั้งหมดใน `supabase/migrations`
3. สร้างบัญชีเจ้าหน้าที่ใน Supabase Auth
4. กำหนดบทบาทใน `raw_app_meta_data.role` เป็น `editor`, `reviewer`, `publisher` หรือ `admin`
5. เปิด `/admin/login` และเข้าสู่ระบบ
6. บัญชี `publisher` หรือ `admin` สามารถกด “นำเข้าชุดข้อมูลเริ่มต้น” ได้เมื่อฐานข้อมูลยังว่าง

ตัวอย่าง SQL สำหรับกำหนดบทบาทโดยผู้ดูแลโครงการ:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb)
  || '{"role":"admin"}'::jsonb
where email = 'ADMIN_EMAIL';
```

ควรกำหนด MFA ในโครงการจริงและเปลี่ยนบทบาทเฉพาะผ่านผู้ดูแล Supabase ผู้ใช้ไม่สามารถแก้ `raw_app_meta_data` ของตนเองได้

## กระบวนการเผยแพร่ที่แนะนำ

1. `editor` เพิ่มหรือแก้ไขข้อมูลเป็น `draft`
2. `reviewer` ตรวจแหล่งอ้างอิง ช่องทางติดต่อ และกฎจับคู่ แล้วเปลี่ยนเป็น `reviewed`
3. `publisher` ตรวจซ้ำและเปลี่ยนเป็น `published`
4. เมื่อข้อมูลไม่ใช้แล้ว เปลี่ยนเป็น `retired` แทนการลบ เพื่อให้ตรวจสอบย้อนหลังได้

MVP อนุญาตให้ทั้งสี่บทบาทแก้ไขตารางผ่าน RLS แต่กระบวนการสองคนตรวจควรเสริมด้วย approval workflow และ audit log ก่อนใช้งานระดับ production

## หลักการจับคู่ข้อความ

ข้อความที่ประชาชนกรอกถูกประมวลผลในเบราว์เซอร์ด้วยคำสำคัญที่เผยแพร่แล้ว ระบบไม่ส่งข้อความดังกล่าวไป Supabase และไม่เก็บข้อความไว้ในฐานข้อมูล ผู้ดูแลจัดการเฉพาะ “คำสำคัญต้นแบบ” เช่น `หลอกโอนเงิน` หรือ `บัญชีถูกแฮก` โดยไม่คัดลอกข้อความจริงของประชาชนเข้าหลังบ้าน
